# NF-P1-007 — Frontend Bootstrap (React + Vite + TypeScript)

## Summary

The frontend scaffold (previously ~90 empty stub files) is now a working **React 18 + Vite + TypeScript** app. `vite.config.ts` wires the `@vitejs/plugin-react` and the `@/*` → `src/*` path alias. `src/main.tsx` mounts `RouterProvider` (React Router v6, `src/router.tsx`, one placeholder route) inside `QueryClientProvider` (TanStack Query v5, `src/lib/queryClient.ts`). **Tailwind CSS v3** and **shadcn/ui** are installed and configured (`tailwind.config.ts`, `components.json`, `src/styles/{tokens,globals}.css`, `src/lib/utils.ts`'s `cn()` helper), with one real primitive — `src/components/ui/button.tsx` — proving the whole chain renders. `src/App.tsx` is a placeholder screen (heading + one `Button`), replaced by the real app shell in NF-P1-010.

Versions were deliberately pinned **behind** npm's `latest` tag wherever the original design or the existing (pre-scaffolded) config files implied an older major: **React 18** (original design, not 19), **React Router v6** (original design, not v7), **ESLint 8** (the scaffold already had `.eslintrc.cjs`, the legacy config format — ESLint 9 needs `eslint.config.js`), **Tailwind v3** (the scaffold already had `tailwind.config.ts`, a classic-config-file setup — Tailwind v4 doesn't use one by default).

No real navigation, Firebase Web SDK, i18n, or PWA config yet — those are NF-P1-010, NF-P1-009, NF-P1-011, NF-P1-012.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `TS5102`/deprecation: `Option 'baseUrl' is deprecated and will stop functioning in TypeScript 7.0` | Remove `baseUrl` from `tsconfig.json`. TS then requires `paths` patterns to be either non-relative (needs `baseUrl`) or explicitly relative (`"./src/*"` instead of `"src/*"`) — use the relative form. No behavior change: `paths` without `baseUrl` already resolves relative to the tsconfig file's own directory, which is what `baseUrl: "."` meant anyway. |
| `TS5090: Non-relative paths are not allowed when 'baseUrl' is not set` | You removed `baseUrl` but left a bare `"src/*"` pattern. Prefix it with `./`. |
| `tsc -b` emits `tailwind.config.js` / `tailwind.config.d.ts` / `vite.config.js` / `vite.config.d.ts` into the repo root | `tsconfig.node.json` is a composite project (required for the `tsconfig.json` project reference) and composite projects must emit — but without an explicit `outDir` they emit next to the source files. Fixed by setting `outDir`/`tsBuildInfoFile` under `node_modules/.tsbuild/` (already gitignored). If you see this again, check `tsconfig.node.json` still has that `outDir`. |
| React Router console warning: `React Router will begin wrapping state updates in React.startTransition in v7` | The `future` flag for this belongs on `<RouterProvider future={{ v7_startTransition: true }}>` in `main.tsx` — **not** on `createBrowserRouter`'s own `future` option, which only covers router-level flags like `v7_relativeSplatPath`. Verified by reading the installed `react-router` source (`logV6DeprecationWarnings`) rather than guessing. |
| ESLint: `react-refresh/only-export-components` warning on `src/components/ui/*.tsx` | Expected — every shadcn/ui primitive exports its `cva()` variants alongside the component. Already suppressed via an `overrides` block in `.eslintrc.cjs` scoped to `src/components/ui/**`. |
| `pnpm lint` fails with `eslint-plugin-react-refresh` peer dependency error after a `pnpm add`/upgrade | That plugin's `0.5.x` line requires ESLint 9. This project pins ESLint 8 (matches the legacy `.eslintrc.cjs` format), so keep `eslint-plugin-react-refresh` on `0.4.26`. |
| `pnpm format:check` fails on files you didn't touch | Check whether they're empty stub files from another task (`README.md`, `src/i18n/*.json`) before "fixing" them — Prettier can't produce a meaningful diff for a 0-byte file either way. |
