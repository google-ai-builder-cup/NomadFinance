# NF-SA-018 — Check history and "Warn other workers"

## Summary

Three things on the scam check feature (`/scam-check`):

| Screen                                        | What a worker gets                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **History**, `/scam-check/history`            | Every check of the last 90 days, newest first. Each row: the kind of scam (or "Not a scam"), a risk badge with the level in words, the first words of the message, the date, whether it was pasted or a screenshot, and "You warned other workers" when they did. A **Show more** button loads the next page (20 at a time). Nothing yet: the `EmptyState` with a way to make the first check |
| **A stored check**, `/scam-check/history/:id` | The same card, explanation and steps as a fresh result, with the day it was checked and the day it will be removed. A check that is gone (older than 90 days, or not theirs: the server answers both the same) says so, with a way back                                                                                                                                                       |
| **Warn other workers**                        | On a scam, on a fresh result and on a stored check. A button opens a **confirmation sheet** that shows exactly what other workers will see; **Send warning** sends exactly that. After it, the button stays **disabled** ("You warned other workers") with a link to the Radar page of this kind of scam                                                                                      |

On the Radar entity page of a kind of scam (`/radar/entity/scam-…`, where the link goes) each scam report now has labels and a compact block of what the reporting worker confirmed (D-124).

No backend change: it reads `GET /scam/checks`, `GET /scam/checks/{id}` and `POST /scam/checks/{id}/report`, which NF-SA-012 and NF-SA-013 built.

## The confirmation sheet

It is the contract's own list (`docs/api/v2-scam.md`, `docs/data-model/collections/radar.md`): what is public, and nothing else.

| On the sheet                                                                                                                                                                                                                                       | Sent as                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| The kind of scam (read only)                                                                                                                                                                                                                       | Not sent: the server takes it from the check                           |
| **The message other workers will see**: a box, filled with the message with numbers, accounts and links already hidden, up to 1,000 characters, with a counter. The hint says to take out any name                                                 | `description`, as the worker leaves it, trimmed                        |
| **Contacts to share**: each phone number, link, address or sender with a tick, all ticked to begin with, up to 10 (more than 10 starts with the first 10 and the rest cannot be ticked until one is cleared). Shown as plain text, never as a link | `indicator_ids`, the ticked ones, in the message's order; may be empty |
| "Also shared: how risky it looks, the tricks it uses and the words that gave it away"                                                                                                                                                              | Taken from the check by the server                                     |
| "This warning is anonymous and not verified. Your name, your account and the original message are never shared."                                                                                                                                   |                                                                        |

A name in the message is not masked by any rule (D-108); the sheet and its hint are where the worker removes it.

**How it behaves.** A bottom sheet on a phone, a centred card from 640 px up. It takes the keyboard (Tab stays inside it, Escape closes it), returns focus to the button that opened it, and locks the page behind it. While a send is in flight it cannot be closed (Escape, Cancel and a tap outside do nothing), so a report is never abandoned half way. **Send warning** is stuck to the bottom of the sheet, so on a short phone it never sits below the fold (found at 640 px height, where it was 258 px off screen). Errors show beside the button:

| Server says        | The sheet says                                               | Send                            |
| ------------------ | ------------------------------------------------------------ | ------------------------------- |
| 409 `not_a_scam`   | Only a message that looks like a scam can be reported        | off                             |
| 404                | This check is no longer saved                                | off                             |
| 422                | Check the message is not empty and is under 1,000 characters | on (the worker edits and sends) |
| 429                | You are sending too fast, wait a minute                      | on                              |
| 5xx, no connection | The usual "try again" wording                                | on                              |

A 5xx is also what the second of two simultaneous taps can get (NF-SA-013); trying again returns the first report, so it is safe to offer.

## After the warning

- **201** (new): "Thank you. Other workers can now see your warning." **200** with `already_reported` (the server had it): "You already warned other workers about this message." Both link to `/radar/entity/{entity_slug}`.
- A check reported on an earlier day opens with the button already disabled and the link, and no thank-you (it is said only for what this visit did). Its stored record has no slug, so the link uses the backend's own rule, `scam-` and the type id with hyphens (`scamEntitySlug`, with a test against the sample). If the backend ever changes that rule, this one function changes with it.
- The history and the stored check are fetched again, so the row shows the marker.

## Decisions

| #   | Decision                                                                                                           | Why                                                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | "Show more" button, not endless scrolling                                                                          | A worker on a slow or metered connection chooses when to spend data; also simpler for a screen reader                                                                       |
| 2   | The sheet is built by hand, like `ReportPreviewModal`                                                              | The project has no dialog component, and a new dependency would touch a shared file                                                                                         |
| 3   | The report button is on the fresh result as well as on a stored check                                              | The analyze answer already carries the check's `id`, and the moment a worker has just seen a scam is the moment they want to warn others                                    |
| 4   | Every contact starts ticked                                                                                        | The contract and the data model say so: the worker unticks what is their own                                                                                                |
| 5   | The text is sent as the worker left it, trimmed, always                                                            | "This request carries exactly that": nothing is left to the server's default                                                                                                |
| 6   | Characters are counted as the server counts them (code points), and the box is never cut in the middle of an emoji | A string's `length` counts an emoji as 2 and a cut could split one                                                                                                          |
| 7   | The disabled button is a real `disabled` button, with the link beside it                                           | The tracker says the call to action is disabled after success; the way on stays                                                                                             |
| 8   | The Radar block shows no "reported N times" and no payment text                                                    | A scam report's contacts have no count (D-104), and the free text of `payment_requested` is written by the model in English; only the amount, which is structured, is shown |
| 9   | The Radar block's strings are fetched with the first scam report shown                                             | A worker who only reads the heatmap never downloads them                                                                                                                    |
| 10  | Strings are written in all six languages now                                                                       | `scripts/check-i18n.mjs` requires every key in every language. They need a native read (D-159)                                                                              |

## Manual test

Dev server with the emulators and the API as in `NF-F0-005-backend-feature-flags.md`, signed in, with the `scam` flag on for the test user. A real check needs a Gemini key; without one use the tests.

1. Check a scam message (or have checks already). On the check screen tap **Your checks**: the list, newest first, with words on every badge.
2. Tap a row: the stored check with its date. Tap **Back to your checks**.
3. With more than 20 checks, **Show more** adds the next 20 and disappears on the last page.
4. With no checks: "No checks yet" and a button to the check screen.
5. On a scam, tap **Warn other workers**. Read the sheet. Edit the text, untick a contact, tap **Send warning**.
6. The sheet closes, the thank-you shows and the button is disabled. Tap **See it in Radar**: the page of this kind of scam, with your report and the contacts you left ticked.
7. Go back to the history: the row says "You warned other workers". Open the check: the button is disabled from the start.
8. Open a check that does not exist (`/scam-check/history/nope`): "We could not find this check".
9. Phone width, 360 px, also 640 px tall: **Send warning** is visible without scrolling. On a real phone: D-158.

## Not done, and why

- **Not tried on a real phone** (D-158). In particular the on-screen keyboard over the sheet's message box, and the Back button: the sheet is not a route, so on Android Back leaves the page instead of closing the sheet.
- **The Radar entity page itself was not opened with a real scam profile**: the block was checked on a temporary page and in tests, not behind the real route (that needs a stored report). The heatmap question is D-160.
- **A screenshot of each screen** could not be captured reliably in the in-app browser's phone emulation; the layout was measured instead.
- **The five other languages were written by the team, not by native speakers** (D-159).
- **No axe run** (NF-SA-019).
- **Names in the message** are not masked (D-108); and a takedown path for a report that wrongly names someone is still open (D-107).

## Noticed, not fixed

- The two screenshot-upload tests in `ScamCheckHome.msw.test.tsx` still fail in this environment (Node 24.13.1, jsdom 29.1.1, msw 2.15.0); see NF-SA-017's runbook. Check the last CI run on `main` before spending time on them.
- A low-risk scam still reads as a green tick next to "Low risk" in a history row and on the card (D-155).
